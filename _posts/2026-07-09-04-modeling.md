# 모델링 — House Prices Prediction

피처 엔지니어링까지 끝내 데이터는 순수 숫자 행렬(`_fe.csv`)이 된 상태입니다. train은 `(1458, 258)`, test는 `(1459, 258)`이고 글자열·NaN·inf는 전부 0입니다. 이번 단계의 목표는 이 행렬로 실제 집값을 예측하는 모델을 세우고, 교차검증으로 모델들을 비교한 뒤 캐글 제출 파일을 만드는 것입니다. 프로젝트의 마지막 단계입니다.

타겟은 03에서 이미 로그를 씌운 `SalePrice_log`입니다. 캐글 이 대회의 평가 지표도 로그를 씌운 SalePrice에 대한 RMSE라, 검증을 로그 상태에서 그대로 재면 리더보드와 같은 기준이 됩니다. 대신 제출할 때는 예측값을 `expm1`로 되돌려 원래 달러 단위 집값으로 바꿔야 합니다.

## 데이터 로드와 검산

03에서 Drive(`/content/drive/My Drive/house-price-prediction/data/`)에 저장해 둔 `_fe.csv` 네 개를 불러왔습니다. 03의 `"None"` 함정은 인코딩으로 이미 숫자가 돼 사라졌지만, 로드 직후 shape·NaN·컬럼 일치를 다시 확인하는 습관은 유지했습니다.

## 검증 틀 — fold마다 스케일러 다시 맞추기

모델을 비교하려면 먼저 공정한 잣대가 필요했습니다. 단일 분할은 우연히 쉬운 검증셋을 뽑을 수 있어, 5-겹 교차검증으로 다섯 번 재고 평균을 봤습니다. 점수는 캐글과 같은 기준이 되도록 로그 타겟에 대한 RMSE(`neg_root_mean_squared_error`)로 통일했습니다.

```python
from sklearn.model_selection import KFold, cross_val_score

kf = KFold(n_splits=5, shuffle=True, random_state=42)

def get_cv_rmse(model, X=X_train, y=y_train, cv=kf):
    scores = cross_val_score(model, X, y,
                             scoring="neg_root_mean_squared_error",
                             cv=cv, n_jobs=-1)
    rmse = -scores
    return rmse.mean(), rmse.std(), rmse
```

여기서 03과 이어지는 원칙 하나를 구조로 옮겼습니다. 03에서는 스케일링·인코딩 통계를 손으로 train에만 맞춰 누수를 막았는데, 교차검증에서는 fold마다 train이 바뀝니다. 스케일러를 미리 한 번 fit해 두면 각 fold의 검증 데이터가 스케일 계산에 섞여 누수가 생깁니다. 그래서 스케일러와 모델을 `Pipeline`으로 묶어, `cross_val_score`가 fold를 나눌 때마다 그 fold의 train으로만 스케일러가 다시 fit되도록 했습니다.

## 베이스라인에서 Ridge 튜닝까지

가장 단순한 선형회귀부터 기준선을 잡았습니다.

```python
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LinearRegression

linear_pipe = Pipeline([("scaler", StandardScaler()),
                        ("model", LinearRegression())])
```

```python

LinearRegression CV RMSE = 0.13066 ± 0.01446
```

fold별 편차가 0.105~0.150으로 제법 컸습니다. 258개 열 중에는 원-핫으로 펼친 희소한 더미가 많아, 선형회귀가 계수를 과하게 잡는 자리가 있어 보였습니다. 그래서 계수 크기에 벌점을 주는 Ridge로 넘어갔습니다. 우선 `alpha=10`으로만 봐도 평균이 내려가고 편차도 줄었습니다.

```python
Ridge(alpha=10.0) CV RMSE = 0.12540 ± 0.01240
```

`alpha`를 감으로 두지 않고 `GridSearchCV`로 여덟 개 후보를 같은 교차검증 틀에서 비교했습니다.

```python
from sklearn.model_selection import GridSearchCV

param_grid = {"model__alpha": [0.1, 0.3, 1, 3, 10, 30, 50, 100]}
ridge_grid = GridSearchCV(ridge_pipe, param_grid=param_grid,
                          scoring="neg_root_mean_squared_error", cv=kf, n_jobs=-1)
ridge_grid.fit(X_train, y_train)
```

```python

Best Ridge CV RMSE = 0.12090
```

후보 중 가장 강한 규제(`alpha=100`)가 최선이었습니다. 벌점을 크게 줄수록 좋아졌다는 건, 그만큼 이 데이터에서 선형 모델이 과적합 쪽으로 쏠리기 쉬웠다는 뜻으로 봤습니다.

## XGBoost

선형 계열의 한계를 확인한 뒤, 트리 기반 부스팅을 같은 검증 틀에 올렸습니다. 학습률을 낮추고(0.02) 트리 개수를 늘린(2000) 대신, 깊이를 3으로 얕게 잡고 표본·열 샘플링(0.8)과 규제를 걸어 과적합을 눌렀습니다.

```python
from xgboost import XGBRegressor

xgb_model = XGBRegressor(
    n_estimators=2000, learning_rate=0.02, max_depth=3,
    subsample=0.8, colsample_bytree=0.8,
    reg_alpha=0.001, reg_lambda=1.0,
    objective="reg:squarederror", random_state=42, n_jobs=-1)
```

```python
XGBoost fold RMSE: [0.11337 0.11117 0.12173 0.12065 0.10330]
XGBoost CV RMSE = 0.11404 ± 0.00674
```

평균이 세 모델 중 가장 낮았고, fold별 편차(±0.0067)도 가장 작아 안정적이었습니다. 원-핫 더미가 많은 희소 행렬에서, 조건 분기로 상호작용을 잡는 트리 쪽이 선형보다 유리했던 것으로 봤습니다.

## 제출 파일

XGBoost를 train 전체로 다시 학습해 test를 예측하고, `expm1`로 로그를 되돌렸습니다. 로그 역변환에서 아주 드물게 음수가 나올 수 있어 0으로 막았습니다. 제출 형식은 캐글이 요구하는 `Id,SalePrice`입니다.

```python
final_model = xgb_model
final_model.fit(X_train, y_train)

pred = np.expm1(final_model.predict(X_test))
pred = np.maximum(pred, 0)

submission = pd.DataFrame({"Id": test_id, "SalePrice": pred})
submission.to_csv("/content/submission.csv", index=False)
```

행 수 1459, 열은 `Id`·`SalePrice`, NaN 0으로 검산을 통과했습니다. `test_id`가 1461부터 시작하는 것도 03에서 보관해 둔 값 그대로라, 예측과 식별자가 어긋나지 않았습니다.

이 `submission.csv`를 캐글에 제출한 결과 Public Score(로그 RMSE)는 **0.12681**이었습니다. 로컬 CV 0.11404보다 약 0.013 높은 값입니다.

## 로컬 CV와 리더보드의 간격

XGBoost의 로컬 CV는 0.11404, 캐글 Public Score는 0.12681로 약 0.013 차이가 났습니다. 이 차이를 어떻게 읽었는지 적어 둡니다.

로컬 CV는 train을 다섯 조각으로 나눠 그 안에서 잰 값이라, 완전히 새로운 데이터인 test보다 다소 낙관적으로 나오기 쉽습니다. 리더보드가 그보다 조금 높게(나쁘게) 나온 것은 이 방향과 맞아떨어졌습니다. 다만 제출은 한 번뿐이었고 Ridge·LinearRegression은 리더보드에 올리지 않았으므로, 이 0.013을 검증이 늘 정확하다는 일반적 근거로 삼지는 않았습니다. 이번 한 번의 결과가 로컬 CV와 크게 어긋나지 않았다는 정도로만 봤습니다.

이어서 04에서 스케일러를 `Pipeline` 안에 넣은 선택도 이 간격과 함께 확인했습니다. 스케일러를 CV 분할 전에 한 번 fit해 두면 검증 fold가 스케일 계산에 섞여 CV만 낙관적으로 좋아지고 리더보드와의 간격이 벌어지기 쉽습니다. 이번에 간격이 크지 않았던 것은 fold마다 스케일러를 다시 fit한 처리가 의도대로 동작했다고 볼 만한 정황이었습니다 — 단정할 근거라기보다 정황으로 기록해 둡니다.

## 정리

이번 단계에서 확인한 것은 두 가지입니다. 하나는 스케일러를 `Pipeline`에 넣어 fold마다 train으로만 다시 fit되게 하니, 03에서 손으로 막던 누수를 구조로 차단할 수 있었다는 점입니다. 다른 하나는 원-핫으로 넓어진 희소 행렬에서 강하게 규제한 Ridge(0.12090)보다 얕은 XGBoost(0.11404)가 평균·편차 모두 앞섰고, 이 선택이 캐글 리더보드(0.12681)에서도 로컬 CV와 큰 간격 없이 이어졌다는 점입니다.

남은 것은 두 갈래입니다. 실제 LightGBM을 더해 Ridge·XGB와 3-모델 앙상블을 구성하는 것, 그리고 03에서 미뤄둔 거의 상수인 열 제거·왜도 임계값·순서형 매핑을 CV 점수로 비교하는 것입니다. 이 선택지들을 점수로 비교해 정리하면 프로젝트를 블로그에 게시해 마무리할 수 있습니다.
